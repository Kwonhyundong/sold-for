# claude_Dev_Profit

집에서, 자본 없이, 자동화된 수익 구조를 만들기 위한 작업 저장소.

## 지금까지의 결론

경로 10개를 조사해서 죽였다. 전부 같은 이유였다 — **수요를 모른다.**

|---|---|
| 오픈소스 바운티 | 바운티 하나에 PR 8~158개. 클로드로 $20 시도 → $0 |
| MCP 서버 판매 | 11,000개 중 과금 5% 미만, pay-per-call $10 초과 수익 66개 |

| 한국 확률형 아이템 공시 진단 | 재직 중 이해상충 |
| 중국 게임사 대상 서비스 | 게임 영역 제외 |
| 소수 고액 B2B 데이터 구독 | 영업 미팅 필수 |
| 1688 소싱 도구 | 포화. 1688 본인이 AlphaShop(7만 사용자) 배포 중 |

**찾은 것**: 작은 제품을 *사는* 게 아니라 *만들어 파는* 쪽. 수요가 가격표로 공개돼 있다.

## 만들고 있는 것

**인디 제품이 실제로 얼마에 팔렸는지 모아놓은 공개 데이터베이스.**

없어서 만든다. 확인해본 결과 공개된 건 전부 *부르는 값*이고
(BigIdeasDB 522건, 평균 $434K), 체결가는 마켓플레이스마다 흩어져 있거나
커뮤니티 글에만 남아 있다. Hacker News 에서 관련 검색은 0건이었다.
$1,000~10,000 소형 구간은 특히 아무도 보지 않는다 — 인디 해커가
실제로 거래하는 구간인데도.

## scout — 수집기

```bash
python3 -m scout.cli collect   # 마켓플레이스 매물 + 체결가
python3 -m scout.cli mine      # 커뮤니티에서 판매 발언 채굴
python3 -m scout.cli review    # 사람이 승인/거절 (하루 1~2시간)
python3 -m scout.cli report    # 리포트
python3 tests/test_hn.py       # 추출기 회귀 테스트
```

외부 라이브러리 없이 파이썬 표준 라이브러리만 쓴다. 유료 API 도 쓰지 않는다.

### 왜 사람의 승인을 거치는가

기계는 후보를 찾는 데까지만 믿을 만하다. 제목에 금액이 없는 글이
있는 글보다 두 배 넘게 많고("Sold My Side Project"), 거래가 아닌 글도
섞여 든다("My old photos appeared on an iPad I sold"). 그래서 채굴 결과는
곧바로 공개되지 않고 `claims.status='pending'` 으로 대기한다.
사람이 원글을 열어 금액을 채우거나 버린다. 재수집은 이미 판정된 건을
덮어쓰지 않는다.

### 왜 스냅샷을 쌓는가

`snapshots` 테이블은 매 수집마다 한 줄씩 쌓인다. 매물이 목록에서 사라지면
`present=0` 으로 기록된다. **사라짐 = 팔렸을 가능성**이므로, 며칠 돌리면
호가가 아니라 *실제 체결*에 가까운 신호를 얻는다. 지금 공개된 건 전부
호가일 뿐이라 이게 필요하다.

### 구조

- `scout/fetch.py` — HTTP 수집 (재시도·백오프)
- `scout/parse.py` — 사이트별 파서. 자기가 읽은 값이 그 카드 안에 있는지 스스로 검증
- `scout/store.py` — SQLite 저장 + 스냅샷
- `scout/analyze.py` — 배수 계산, 파는 쪽 관점 집계
- `scout/cli.py` — 명령줄

사이트 HTML이 바뀌면 `parse.py` 만 고치면 된다.
